# Understand 수동 증분 분석 가이드

**대상**: weaver2 모노레포 (`understand-anything` 지식 그래프)
**방식**: 수동 증분 (auto-update 미사용)
**최초 분석**: 완료 (commit `24ca570`, 754 파일 / 1267 노드 / 2699 엣지 / 10 레이어 / 13 투어)

> **한 줄 요약**: 최초 1회 풀스캔 이후엔 `/understand`를 다시 돌리기만 하면 **변경된 파일만** 재분석해 그래프를 갱신합니다. 매번 754개를 통째로 돌 필요가 없습니다.

---

## 🧭 개요 — 증분이 가능한 원리

최초 풀스캔이 끝나면 `.understand-anything/`에 다음이 저장됩니다.

| 파일 | 역할 |
|------|------|
| `knowledge-graph.json` | 전체 지식 그래프 (노드·엣지·레이어·투어) |
| `meta.json` | **마지막 분석 시점의 git commit hash** 보관 |
| `fingerprints.json` | 소스 666개의 **구조 지문(baseline)** — 증분 판단 기준 |
| `.understandignore` | 분석 제외 규칙 |

재실행 시 도구는 `meta.json`의 커밋과 현재 `HEAD`를 비교해 **달라진 파일만** 골라 재분석합니다.

---

## ✅ 사전 조건

1. **최초 풀스캔이 완료돼 있어야 함** → 이미 완료 (위 메타 참조).
2. `.understand-anything/meta.json` 과 `fingerprints.json` 이 **삭제되지 않고 보존**돼 있어야 함.
   - 이 둘이 없으면 증분이 불가능해 도구가 풀스캔으로 되돌아갑니다.

---

## 🔁 수동 증분 실행 절차

### 1. 코드 변경 후 커밋

```bash
git add -A
git commit -m "feat: ..."
```

> 증분 비교는 **커밋 단위**(`git diff <last>..HEAD`)로 동작합니다.
> 커밋되지 않은 변경분은 정확히 잡히지 않을 수 있으니, 먼저 커밋하는 것을 권장합니다.

### 2. understand 재실행

```
/understand
```

도구가 자동으로 판단합니다:

| 상황 | 도구 동작 |
|------|-----------|
| 커밋 hash가 그대로 (변경 없음) | "최신 상태" 안내 후 종료 |
| 변경된 파일 존재 | **증분 업데이트** — 변경 파일만 재분석 |
| 기존 그래프/메타 없음 | 풀스캔 |

### 3. 내부 동작 (증분 경로)

1. `git diff <meta의 commit>..HEAD --name-only` 로 변경 파일 목록 추출
2. 변경된 파일이 속한 배치만 file-analyzer로 **재분석**
3. 기존 그래프에서 해당 파일의 노드·엣지를 제거하고 새 결과로 교체
4. 레이어(Phase 4)·투어(Phase 5)를 **전체 노드 기준으로 재계산**
5. 검증 후 `knowledge-graph.json` / `meta.json` / `fingerprints.json` 갱신

→ 무거운 파일 분석 단계가 **변경분만큼만** 돌기 때문에, 파일 몇 개 수정 정도면 거의 순식간입니다.

## 🚨 언제 풀스캔(`--full`)이 필요한가

아래처럼 **구조가 크게 흔들리는 변경** 후엔 한 번 풀스캔으로 새로 잡는 것이 깔끔합니다.

```
/understand --full
```

- 디렉토리/모듈 구조 대규모 재편 (예: `features/` → `domains/` 이동)
- 대량 파일 이동·삭제·이름 변경
- 새 앱/라이브러리(`apps/*`, `libs/*`) 추가
- 레이어 경계가 바뀔 만한 아키텍처 리팩터

> 일상적인 기능 추가·버그 수정은 **증분으로 충분**합니다. `--full`은 가끔 구조가 바뀌었을 때만.

## ⚠️ 주의사항

1. **Phase 4(레이어)·Phase 5(투어)는 매번 전체 재계산됩니다.**
   파일 한 개만 바뀌어도 레이어 배치가 흔들릴 수 있어 전체를 다시 돕니다. 단, 이 둘은 가벼운 단계라 부담이 적습니다.
2. **`fingerprints.json`을 지우지 마세요.**
   삭제되면 증분이 구조적 변경을 구분하지 못해 매번 풀스캔으로 escalation 됩니다.
3. **`.understand-anything/` 커밋 여부는 팀 정책으로 결정하세요.**
   - 커밋함: 팀원이 풀스캔 없이 그래프 공유 가능 (단, 충돌·diff 노이즈 발생 가능)
   - 커밋 안 함(`.gitignore`): 각자 로컬에서 한 번 풀스캔 후 증분 운용 (권장 기본값)
4. **출력 언어는 한국어(ko)** 로 설정돼 있습니다 (`config.json`의 `outputLanguage`). 증분 시에도 동일 유지됩니다.
