- **참여**: 주인님(방향 결정) · 노엘(설계 정리) · 독립 크리틱 에이전트(적대 검토)

## 1. 배경 — 던져진 질문

CHARTER가 weaver2를 "범용 레코드-CRUD 기반 + 배터리 보일러플레이트"로 재정의한 뒤(2026-07-02, `ca60102`·`2adfec1`), 자연스럽게 따라온 질문:

> "어떤 테이블(엔티티)이 와도 **최소한의 코드만 추가하면** CRUD 화면과 API가 만들어지는 템플릿이어야 하는가?"

이 문장은 하나의 목표처럼 들리지만 실제로는 세 가지 서로 다른 만듦새로 갈라지며, 어느 쪽이냐에 따라 로드맵이 통째로 달라진다.

## 2. 검토한 대안

| 대안 | 내용 | 판단 |
|------|------|------|
| **런타임 제네릭 엔진** | 엔티티 메타데이터 등록만으로 API·화면이 런타임 생성 (Directus/Django admin류) | ❌ 커스터마이징 절벽, 타입 안전성·CQRS 파일 분리 정체성과 충돌, §5.1 기준 "상상 기반 일반화" |
| **스캐폴드 CLI 코드젠** | `pnpm gen:crud` 결정적 제너레이터가 템플릿에서 파일 생성 | ❌ 템플릿이 제2의 유지보수 대상 — substrate 변경마다 이중 관리 |
| **패턴 + AI 레시피** | 레시피 문서(스킬)를 따라 AI가 표준 세트를 조립. 결과물은 전부 소유하는 평범한 코드 | ✅ **채택** — CHARTER §1 "(AI와 함께) 조립" 미션·§5.1 pull-not-push에 부합, 마법 없음 |

### 레퍼런스 엔티티에 대한 결정 (가이드만으로 불충분한가?)

살아있는 레퍼런스 엔티티의 값어치(컴파일러가 드리프트 감지 / AI 복제 충실도 / 레시피의 테스트 타깃)와 비용(가짜 도메인 상주, fork 체크리스트 증가)을 비교한 결과:

- **가이드 우선.** 코드 예시는 이미 존재한다 — 게시판(백엔드 spec 제외 67파일). 가이드가 게시판의 코어/특수 경계를 정밀하게 그어주면 복제 충실도 문제는 상당 부분 해소된다.
- "AI가 가이드+게시판만으로 헤맬 것"은 아직 fork 0회인 현시점엔 **상상 기반 우려**다. §5.1 렌즈 1(증거 기반)에 따라, **실전에서 반복적으로 헤매는 증거가 나오면 그때** 미니멀 예시를 본체에 추가한다.

## 3. 비판 재검토 기록 (v1 → v2 변경 사유)

v1 승인 직후 "이 방향이 좋은지 한 번 더 비판적으로 보자"는 주인님 요청으로, 노엘 자체 재검토 + 독립 크리틱 에이전트의 적대 검토를 수행했다. 방향(패턴 + AI 레시피)은 유지하되, 다음 지적을 수용해 v2로 수정한다:

1. **레시피 선제 작성의 §5.1 자기모순** — fork 0회 시점에 상세 레시피를 완성하는 것은 게시판 1개 사례(Rule of Three의 1회)를 3회처럼 다루는 것. → **지금은 최소 골격만, 상세는 첫 실전 fork에서 채운다.**
2. **가상 엔티티 리허설은 순환 검증** — `inventory`류는 게시판의 스칼라 변형이라 레시피 없이도 AI가 조립 가능. "레시피 덕인지"를 구분 못 한다. → **합성 리허설 폐기, 실전 fork #1이 검증을 대체.** (주인님 확인: 가까운 시일 내 실제 fork 계획 있음)
3. **문서 부패(rot)는 이 리포에서 이미 관측된 현실** — CHARTER §7.3 gitignore 서술 ≠ 실제 `.gitignore`, CLAUDE.md가 안내하는 `nestjs-best-practices` 스킬 부재, `.claude/skills/` 심링크 디렉토리 부재. → **죽은 참조 선행 정정 + 레시피에 신선도 규칙 내장.**
4. **"관리자 화면 완전 표준화"는 과잉 약속** — 목록은 표준화돼도 생성/수정 폼은 관계 필드·enum·리치텍스트에서 케이스별 수작업 불가피. → **"골격 표준"으로 약속 하향.**
5. **빠져 있던 관점 (의도적 defer로 기록)** — fork된 리포에서의 레시피 수명(fork마다 갈라짐), 삭제·이름변경·마이그레이션 충돌 시나리오(현재는 "추가"만 다룸). 첫 fork 경험 후 필요가 끌어당기면 다룬다.

## 4. 확정된 결정 요약 (v2)

1. **방식**: 패턴 + AI 레시피 (런타임 엔진 ❌, CLI 코드젠 ❌)
2. **화면 범위**: 관리자 3화면(목록·생성·상세/수정) **골격 표준** + 공개 목록/상세 기본형. 목록(WeaverDataTable)은 높은 표준화, 폼은 골격 + 필드 타입별 케이스 안내
3. **레퍼런스**: 가이드 우선 — 게시판 코어를 포인터로 지정. 미니멀 예시 추가는 증거가 끌어당길 때만
4. **코어 경계 (슬림 코어)**: CRUD 5종 API(CQRS 파일 분리) + `PERMISSIONS` 상수·가드 + soft-delete·audit 필드 + keyset 목록 + 관리자 필터·정렬. 첨부·풀텍스트 검색·알림은 옵션 add-on 섹션
5. **형태**: 프로젝트 스킬 `.agents/skills/weaver-crud-recipe/` (+ `.claude/skills` 심링크 — 현재 부재하므로 신설)
6. **작성 시점 (v2 핵심 변경)**: 지금은 **최소 골격**(SKILL.md 1장 — 표준 세트 정의 + 코어/특수 경계선 선언)만 작성. 상세 `references/*`는 **첫 실전 fork에서 엔티티를 실제로 얹으며** 그 경험으로 채운다 — 레시피가 상상이 아닌 증거의 기록이 되도록.

## 5. 산출물 설계 — `weaver-crud-recipe` 스킬

### 5.1 지금 만드는 것 (최소 골격)

```
.agents/skills/weaver-crud-recipe/
  SKILL.md    ← 트리거("새 엔티티/CRUD 추가"), 슬림 코어 표준 세트 정의,
                게시판 코어/특수(대댓글·리액션·고정·카테고리) 경계선 선언,
                미러링할 게시판 코어 파일 목록 (심볼 수준 포인터)
```

### 5.2 첫 실전 fork에서 채우는 것

```
  references/
    backend.md      ← prisma model → migration → PERMISSIONS → 시드 매핑 → CQRS 4층
    admin-ui.md     ← WeaverDataTable 목록+필터·정렬 / 폼 골격 + 필드 타입별 케이스
    public-ui.md    ← 공개 목록/상세 기본형
    addons.md       ← 첨부파일 / 풀텍스트 검색 / 알림 연동
```

### 5.3 공통 원칙

- 포인터는 **파일·심볼 수준**(예: `post.controller.ts`의 `findAll`) — 라인 번호 금지 (rot 방지)
- 산문 지시보다 구체 코드 지시 우선 (few-shot 원리)
- 기존 컨벤션 재선언 금지 — `weaver-coding-standards`·`weaver-ui-patterns` 스킬 참조만
- prisma 규칙: FK 컬럼명 `{참조테이블명}Id`, soft-delete(`deletedAt`)·audit(`createdAt`/`updatedAt`) 필드
- 테스트 포함: 코어 레시피에 서비스 유닛 테스트 단계 포함. e2e는 선택 노트
- **신선도 규칙 내장**: SKILL.md 머리에 "fork 시작 시 이 스킬의 포인터가 현재 코드와 일치하는지 확인" 절차를 명시 — 매 fork가 레시피의 회귀 테스트를 겸함

## 6. 검증 계획 — 실전 fork #1이 곧 검증

1. 첫 실제 신규 프로젝트 fork에서 도메인 엔티티를 **골격 SKILL.md를 따라** AI가 조립
2. 성공 기준: lint·typecheck·기존 테스트 전부 통과 + 표준 세트 완성 + 사람 리뷰에서 컨벤션 위반 0
3. 피드백 루프: 헤맨 지점·부족한 안내 → 그 자리에서 `references/*`로 문서화 (base 리포에 역이식). 반복해서 헤매는 구조적 지점 → 그때 미니멀 예시를 본체에 추가
4. (v1의 가상 엔티티 리허설은 순환 검증이라 폐기 — §3-2)

## 8. 의도적으로 하지 않는 것

- CLI 코드젠 도입 / 런타임 제네릭 엔진
- 게시판을 코어/확장으로 분해하는 리팩토링 (동작 중인 67파일 대수술 + 회귀 위험)
- 미니멀 레퍼런스 엔티티 선행 추가 (증거가 끌어당기면 그때 — §5.1)
- 가상 엔티티 합성 리허설 (순환 검증 — §3-2)
- fork된 리포 간 레시피 동기화 체계, 삭제·마이그레이션 충돌 레시피 (첫 fork 후 재검토)
