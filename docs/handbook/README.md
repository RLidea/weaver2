## 추천 읽기 순서

- **처음 합류했다면**: 00 → 01 → 02 를 먼저 읽고 개발 환경을 띄워보세요 (설치는 [README](../../README.md#-시작하기)).
  이후 03(인증) → 04(권한)까지 읽으면 보호된 API 하나를 처음부터 끝까지 추적할 수 있습니다.
- **새 기능을 맡았다면**: 10(새 기능 만들기)을 열고, 필요할 때 해당 도메인 챕터(03~08)를 참조하세요.
- **특정 버그를 쫓는다면**: 해당 도메인 챕터의 플로우 다이어그램에서 시작해 코드 앵커를 따라가세요.

## 이 문서를 믿어도 되는 이유 (그리고 한계)

- 각 챕터는 작성 시점의 **실제 코드를 추적하며** 작성되었고, 파일 경로·심볼 수준으로 앵커링되어 있습니다.
- 다만 코드가 먼저 바뀌고 문서가 따라가지 못할 수 있습니다. 문서와 코드가 다르면 **코드가 진실**이며, 발견 시 해당 챕터를 함께 고쳐주세요 (CHARTER §10 "살아있는 문서"와 같은 원칙).
